# Verification checklist

Use this checklist for rule-heavy coding, imports, validation, character creation, derived statistics, powers, merits, contracts, arcana, conditions, combat rules, or data migrations.

Before changing code/data:
- Identify the game line.
- Identify the edition.
- Identify whether the rule is official or homebrew.
- Identify the source book and, when available, page/reference.
- Confirm the book is Rule Version `2` or `1 & 2`.
- Check whether a game-line-specific rule overrides Core.

Before finishing:
- Search changed data for first-edition-only contamination.
- Search for similarly named mechanics from another WoD/CofD line.
- Ensure exact costs, prerequisites, dice pools, ratings, and exceptions were verified rather than inferred.
- Ensure tests cover at least one normal case and any source-defined boundary/exception relevant to the change.
- If the source was unavailable, clearly mark unresolved facts instead of manufacturing defaults.

Red flags that require verification:
- "usually", "probably", "like D&D", "in World of Darkness", "I think"
- an exact number recalled from memory
- a trait with the same name in multiple game lines
- a book whose edition is not explicit
- use of a first-edition wiki page to patch a second-edition gap
